Programmation fonctionnelle en Python : Arbre binaire

Document 1

Avertissement
  • On se limite dans ce document aux arbres binaires dans lesquels seules les feuilles possèdent des valeurs.
  • La définition d’un arbre binaire présentée dans ce document n’autorise pas à cet arbre d’être vide.

1 Définition du type abstrait “Arbre binaire”

On adopte ici une approche inspirée des langages fonctionnels :

  • données immuables
  • typage statique vérifiable
  • définition inductive des structures

1.1 Code

from __future__ import annotations
from dataclasses import dataclass
from typing import TypeAlias
from numbers import Real

# Type somme : un arbre est soit une feuille, soit un nœud
Tree: TypeAlias = "Leaf | Node"

@dataclass(frozen=True)
class Leaf:
    val: Real

@dataclass(frozen=True)
class Node:
    left: Tree
    right: Tree

1.2 Points théoriques

1.2.1 Type somme

L’instruction :

Tree: TypeAlias = "Leaf | Node"

déclare qu’un objet de type Tree est soit une feuille (Leaf), soit un nœud (Node).

On construit ainsi un type somme. Un arbre est donc défini par analyse de cas.

Astuce

On dit qu’on effectue une analyse de cas lorsqu’on traite séparément chacune des formes possibles d’une donnée.

1.2.2 Type récursif

Un nœud (Node) contient deux objets de type Tree.

La définition est donc récursive :
un arbre est défini en fonction de lui-même.

C’est une définition inductive :

  • Cas de base : une feuille.
  • Cas inductif : un nœud contenant deux arbres.

1.2.3 Pourquoi utiliser Real ?

Le type Real (module numbers) regroupe les nombres réels au sens large :

  • int
  • float
  • Fraction

On indique ainsi que la valeur d’une feuille est un nombre réel, sans restreindre inutilement le type.

1.2.4 Pourquoi dataclass(frozen=True) ?

Le décorateur dataclass permet :

  • une définition déclarative de structures
  • un constructeur automatique
  • une comparaison structurelle

L’option frozen=True rend les objets immuables.

Une fois créé, un arbre ne peut plus être modifié.
Cela garantit la stabilité des invariants.

2 Exemple de création d’un arbre

t = Node(
    Leaf(3),
    Node(
        Node(
            Leaf(8),
            Leaf(12)
        ),
        Leaf(7)
    )
)

Représentation schématique :

        Node
       /    \
    Leaf(3)  Node
             /   \
          Node    Leaf(7)
         /    \
     Leaf(8)  Leaf(12)

3 Pattern matching

Le pattern matching permet d’analyser la forme d’une donnée.

match t:
    case Leaf(v):
        ...
    case Node(l, r):
        ...

On ne teste pas seulement le type : on décompose la structure.

C’est l’équivalent d’une analyse de cas sur un type somme.

3.1 Hauteur de l’arbre

def height(t: Tree) -> int:
    match t:
        case Leaf(_):
            return 1
        case Node(l, r):
            return 1 + max(height(l), height(r))

print(f"La hauteur de l'arbre est : {height(t)}")
La hauteur de l'arbre est : 4

Convention adoptée :

  • une feuille a une hauteur 1 ;
  • un nœud a une hauteur égale à : 1 + hauteur maximale de ses sous-arbres.

La fonction suit exactement la structure inductive du type.

3.2 Somme des valeurs

def sum_tree(t: Tree) -> Real:
    match t:
        case Leaf(v):
            return v
        case Node(l, r):
            return sum_tree(l) + sum_tree(r)

print(f"La somme des valeurs contenues dans l'arbre est égale à {sum_tree(t)}")
La somme des valeurs contenues dans l'arbre est égale à 30

Cette fonction est :

  • pure (aucun effet de bord) ;
  • récursive ;
  • structurée selon la définition du type.

4 Invariant structurel

Dans notre définition :

  • seules les feuilles possèdent des valeurs ;
  • les nœuds ne contiennent que des sous-arbres.

Cet invariant est garanti par la définition des classes.

On ne peut pas créer un nœud contenant directement un nombre réel :

Node(3, 4)  # erreur de typage

La structure impose la cohérence.

5 Ce que montre cet exemple

On a construit :

  • un type algébrique simulé en Python ;
  • un type récursif ;
  • des fonctions définies par récursion structurale ;
  • des données immuables ;
  • un typage statique vérifiable (via Pyright ou mypy).

Cette approche rapproche Python d’un style fonctionnel rigoureux, sans changer de langage.
